## 1. บทบาทและฐานทางกฎหมายในการประมวลผลข้อมูล

เพื่อให้สอดคล้องกับพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA):

1.1 **ร้านค้า (โรงแรมสัตว์เลี้ยง / รับฝากสัตว์เลี้ยง / เดย์แคร์สัตว์เลี้ยง) = ผู้ควบคุมข้อมูลส่วนบุคคล (Data Controller)** ร้านเป็นผู้กำหนดวัตถุประสงค์และวิธีการประมวลผลข้อมูลของลูกค้าของตนเอง และเป็นผู้มีหน้าที่จัดหาฐานทางกฎหมายที่เหมาะสมสำหรับการประมวลผลแต่ละกิจกรรม

1.2 **ร้านค้ามีหน้าที่ของตนเองต่อเจ้าของสัตว์เลี้ยง** กล่าวคือ ร้านต้องแจ้งให้เจ้าของสัตว์เลี้ยงทราบ และ/หรือขอความยินยอมจากเจ้าของสัตว์เลี้ยงตามฐานทางกฎหมายที่ร้านเลือกใช้ (เช่น ความยินยอม การปฏิบัติตามสัญญา หรือประโยชน์โดยชอบด้วยกฎหมาย) ก่อนที่ร้านจะบันทึกข้อมูลของเจ้าของสัตว์เลี้ยงเข้าสู่ระบบ และก่อนส่งรายงานประจำวันทาง LINE ให้แก่เจ้าของสัตว์เลี้ยง WSTERA ไม่ได้เป็นผู้ขอความยินยอมนั้นแทนร้าน และไม่รับหน้าที่นั้นแทนร้าน

1.3 **WSTERA = ผู้ประมวลผลข้อมูลส่วนบุคคล (Data Processor)** WSTERA ประมวลผล จัดเก็บ และส่งต่อข้อมูลตามคำสั่งของร้านเท่านั้น และไม่ใช้ข้อมูลของร้านเพื่อวัตถุประสงค์ของตนเอง ผู้ให้บริการเป็นบุคคลธรรมดา (ยังไม่จดทะเบียนบริษัท) ชื่อตามกฎหมายและที่อยู่ตามกฎหมายยังรอการระบุ: `[[OWNER INPUT: OI-01]]`

1.4 เอกสารนี้ไม่ใช่สัญญาประมวลผลข้อมูล (DPA) ฉบับสมบูรณ์ระหว่างร้านกับ WSTERA หากต้องใช้ DPA ให้ถือว่าเป็นเอกสารแยกที่ต้องจัดทำและอนุมัติก่อนใช้จริง

## 2. ข้อมูลที่ประมวลผลและเหตุผล

ระบบประมวลผลข้อมูลส่วนบุคคลประเภทต่อไปนี้:

2.1 **บัญชีพนักงานของร้าน** — ชื่อ อีเมล บทบาท (owner / manager / staff) และสถานะการใช้งาน การยืนยันตัวตนใช้ Supabase Auth แบบอีเมลและรหัสผ่าน ระบบจะอ่านบริบทของพนักงานผ่านฟังก์ชัน RPC และตัดสิทธิ์ทันทีเมื่อพนักงานถูกตั้งค่าไม่ให้ใช้งาน
`[src: docs/PRD.md:142] [src: lib/tenant-context.ts:41-43] [src: supabase/migrations/20260820030000_phase3_auth_tenant.sql:63-72]`

2.2 **ข้อมูลติดต่อของเจ้าของสัตว์เลี้ยง** — ชื่อ นามสกุล เบอร์โทรศัพท์ เบอร์โทรฉุกเฉิน ที่อยู่ และตัวระบุ LINE ของเจ้าของ (เมื่อเชื่อมแล้ว)
`[src: supabase/migrations/20260220000000_initial_schema.sql:38-55]`

2.3 **ข้อมูลสัตว์เลี้ยง** — ชื่อชนิด สายพันธุ์ เพศ วันเกิด น้ำหนัก หมายเหตุการดูแลพิเศษ และข้อมูลการแพ้
`[src: supabase/migrations/20260220000000_initial_schema.sql:57-63] [src: lib/google-sync-source.ts:16-18]`

2.4 **ประวัติการจอง** — รายการจอง ห้องพัก วันที่เข้าพัก/ออก จำนวนเงิน สถานะการจอง และคำขอพิเศษ รวมถึงคำขอจองที่ลูกค้าส่งเองผ่าน LINE
`[src: supabase/migrations/20260220000000_initial_schema.sql:101] [src: supabase/migrations/20260822000000_phase11_customer_booking_requests.sql:6-26]`

2.5 **เนื้อหารายงานประจำวันและรูปถ่าย** — วันที่รายงาน สถานะอาหาร/การขับถ่าย/อารมณ์ ข้อความที่พนักงานเขียน และรูปถ่าย 1–4 รูปต่อรายงาน
`[src: supabase/migrations/20260220000000_initial_schema.sql:139-159] [src: lib/daily-report-media.ts:4]`

2.6 **บันทึกทางเทคนิคที่จำเป็น** — ข้อผิดพลาดของระบบ ความล้มเหลวของฐานข้อมูล การส่ง LINE ที่ล้มเหลว การซิงก์ Google Sheets ที่ล้มเหลว การอัปโหลดไฟล์ที่ล้มเหลว และการยืนยันตัวตนที่ล้มเหลว เพื่อความปลอดภัยและการแก้ปัญหา โดยตัวบันทึกของระบบถูกออกแบบให้ปิดบังค่าเป็นความลับก่อนเขียน
`[src: docs/PRODUCTION_OPERATIONS.md:32-39] [src: lib/logger.ts:1-35]`

2.7 **โมดูลกล้องผู้มาเยือน (ถ้าร้านเปิดใช้)** — ระบบมีโมดูลกล้องสำหรับผู้มาเยือนแยกต่างหาก ซึ่งบันทึกร่องรอยการเข้าดูแบบเพิ่มอย่างเดียว (append-only) และเก็บที่อยู่ไอพีในรูปค่าแฮชที่ผสมกุญแจลับ ไม่ได้เก็บไอพีดิบ
`[src: supabase/migrations/20260821150000_phase8_camera_access.sql:39-46] [src: lib/camera-access-core.ts:49-51]`

2.8 **เหตุผลในการประมวลผล** — (ก) เพื่อให้บริการตามสัญญากับร้าน (บัญชีพนักงาน ตารางห้อง การจอง รายงานประจำวัน การส่งรายงานให้เจ้าของสัตว์เลี้ยง) (ข) เพื่อปฏิบัติตามหน้าที่ตามกฎหมาย (เอกสารทางบัญชี/ภาษี ซึ่งร้านเป็นผู้รับผิดชอบหลัก) (ค) เพื่อประโยชน์โดยชอบด้วยกฎหมายของร้านและของผู้ให้บริการ (ความปลอดภัยของระบบ ป้องกันการทุจริต) และ (ง) ความยินยอม เฉพาะกรณีที่ร้านเลือกใช้ความยินยอมเป็นฐานสำหรับการส่งรายงานหรือการสื่อสารกับเจ้าของสัตว์เลี้ยง

2.9 **ระบบนี้ไม่มีเครื่องมือวิเคราะห์เพื่อการโฆษณาหรือการติดตามพฤติกรรม** ไม่มีการโฆษณาของบุคคลที่สาม ไม่มีพิกเซลติดตาม และไม่มีการขายข้อมูลให้บุคคลอื่น
`[src: docs/TERMS_AND_PRIVACY.md:20]` (ข้อความยืนยันนโยบายไม่แสวงหาประโยชน์จากข้อมูล) — การไม่มีอยู่ของเครื่องมือวิเคราะห์เป็นผลจากการตรวจโค้ด ไม่ใช่การอ้างความสามารถ: **ดูหลักฐานการตรวจในไฟล์บันทึกงาน `docs/house-swarm-5a/WU3-LEGAL-BILINGUAL.md`**

## 3. กรรมสิทธิ์ในข้อมูล

3.1 ข้อมูลของเจ้าของสัตว์เลี้ยงและสัตว์เลี้ยง ข้อมูลการจอง ประวัติ และรูปถ่ายรายงานประจำวันทั้งหมดที่บันทึกผ่านระบบ **เป็นของร้านค้า** ไม่ใช่ของ WSTERA

3.2 WSTERA **ไม่ขาย ไม่ให้เช่า ไม่เผยแพร่ต่อบุคคลภายนอกที่ไม่เกี่ยวข้อง และไม่ใช้ข้อมูลของร้านเพื่อการตลาดของตนเอง** ทั้งนี้ WSTERA อาจเปิดเผยข้อมูลเท่าที่จำเป็นต่อผู้ประมวลผลช่วงที่ระบุในข้อ 5 เท่านั้น

3.3 เจ้าของสัตว์เลี้ยงต้องติดต่อร้านค้าเพื่อใช้สิทธิของตนในฐานะเจ้าของข้อมูล เพราะร้านเป็นผู้ควบคุมข้อมูล (ดูข้อ 7)

## 4. ระบบที่ใช้จริงและที่จัดเก็บข้อมูล

เอกสารนี้บรรยายระบบที่สร้างไว้จริงในที่เก็บนี้ ไม่ใช่ระบบที่คาดหวังในอนาคต

`[src: lib/line-transport.ts:1] [src: lib/line-transport.ts:40] [src: lib/line-worker.ts:94]`

4.4 **การส่งออก Google Sheets เป็นสำเนาที่ร้านเป็นผู้เริ่มเอง** — การซิงก์ Google Sheets เป็น **สำเนาส่งออกทางเดียว (One-way Export Replica)** ไปยังบัญชี Google ของร้านเอง โดยร้านต้องเป็นผู้ผูกชีตของตนเองผ่านโทเคนยืนยัน สำเนานี้ครอบคลุมเฉพาะข้อมูลลูกค้าและรายการจองแบบ Pet-Centric เท่านั้น **ไม่ครอบคลุมไฟล์รูปภาพใน Storage และไม่ครอบคลุมข้อมูลรายงานประจำวันเชิงลึก**

4.6 **การแยกข้อมูลระหว่างร้าน (Tenant Separation)** — ข้อมูลของแต่ละร้านถูกแยกด้วย Supabase Row-Level Security โดยทุกตารางธุรกิจหลักเปิดใช้ RLS และนโยบายการอ่านถูกผูกกับรหัสร้านของผู้ใช้ที่ยืนยันตัวตนแล้ว เบราว์เซอร์อ่านได้ผ่าน RLS แต่ไม่มีสิทธิ์ INSERT/UPDATE/DELETE ทั่วไปบนตารางธุรกิจหลัก การแก้ไขข้อมูลต้องผ่านฟังก์ชัน RPC หรือบริการฝั่งเซิร์ฟเวอร์ที่กำหนดร้าน บทบาท และเงื่อนไขความถูกต้องเอง ส่วนสิทธิ์ระดับ service role ใช้ได้เฉพาะเซิร์ฟเวอร์/เวิร์กเกอร์ที่เชื่อถือได้เท่านั้น เอกสารเดิมของระบบเรียกโครงนี้ว่า RLS สองชั้น (2-Tier) ซึ่งเป็นคำเรียกตามเอกสาร ไม่ใช่กลไกที่แยกออกมาต่างหาก

6.4 ค่าในข้อนี้จะใช้ได้จริงเมื่อระบบมีกลไกลบข้อมูลที่ตรวจสอบได้ จึงต้องมีการยืนยันก่อนใช้จริง ไม่ใช่เพียงประกาศไว้

## 9. การชำระเงิน (เมื่อเปิดใช้)

9.1 **วันนี้ PS01 ยังไม่มีระบบเรียกเก็บเงินในผลิตภัณฑ์** ไม่มีหน้าชำระเงิน ไม่มีผู้ให้บริการรับชำระเงินที่เชื่อมไว้ และไม่มีคีย์ผู้ให้บริการรับชำระเงินในที่เก็บโค้ดนี้
`[src: lib/entitlements.ts:2]` (ระบุว่า "Billing execution and hard quota enforcement are intentionally outside this phase.") และตรวจไม่พบโค้ดหรือแพ็กเกจของผู้ให้บริการรับชำระเงินในที่เก็บนี้ — หลักฐานการตรวจอยู่ในไฟล์บันทึกงาน

9.2 **เมื่อเปิดใช้การชำระเงิน** ข้อกำหนดการชำระเงิน (ผู้ให้บริการรับชำระเงิน ช่องทาง กำหนดเวลาเรียกเก็บ การต่ออายุอัตโนมัติ การคืนเงิน และหน้าที่ด้านภาษี) จะประกาศในเอกสารนี้และหน้าชำระเงินก่อนเริ่มเรียกเก็บเงินจริง: `[[OWNER INPUT: OI-09]]` การชำระแพ็กเกจรายเดือนครั้งแรกขอคืนเงินได้ภายใน 7 วันนับจากวันชำระครั้งแรก

9.3 **ไม่มีข้อความใดในเอกสารนี้ระบุว่าผู้ให้บริการรับชำระเงินรายใดเปิดใช้อยู่จริง** การกล่าวถึง Stripe PromptPay หรือผู้ให้บริการอื่นในเอกสารอื่นของโครงการไม่ถือเป็นความจริงของผลิตภัณฑ์วันนี้ และเอกสารนี้ไม่กล่าวอ้างเช่นนั้น

9.4 จนกว่าจะเปิดใช้การชำระเงิน การใช้ระบบไม่ก่อให้เกิดค่าบริการเรียกเก็บผ่านระบบนี้
